# M - Brackets · 解题思路

## 一句话思路

把"可翻转的位置"分成 **A 型**（`S_i=')'，T_i='('`，翻后变 `(`，收益 `a_i − b_i`）与 **B 型**（`S_i='('，T_i=')'`，翻后变 `)`，收益 `b_i − a_i`）。由于括号总数必须守恒，翻转必须 **A、B 各翻一个成对进行**。每次贪心取"当前收益最大的一对"翻转（A 左 B 右永远安全；B 左 A 右要求中间前缀 ≥ 2），线段树维护"最大可行对"并支持区间前缀加减与删点。

## 一、模型转化

设 `pref[i]` 为 `S` 的前缀和（`(` = +1，`)` = −1），`pref[n] = 0`。

翻转位置 `i` 对前缀的影响是一个后缀偏移：

- **A 型**（`')'→'('`）：`pref[j] += 2` 对一切 `j ≥ i`（前缀只会更高，安全）；
- **B 型**（`'('→')'`）：`pref[j] -= 2` 对一切 `j ≥ i`（危险，需要裕度）。

因为 `S`、`T` 的正则性保证二者的 `(` 数量相同，所以可翻位置中 A 型与 B 型数量相等（记为 `m`）。合法翻转集合必须满足：

1. **配对**：翻转的 A 数 = 翻转的 B 数 = `c`（否则 `(` 总数失衡）；
2. **前缀非负**：对每个 `j`，`pref[j] + 2·#A(≤j) − 2·#B(≤j) ≥ 0`。

总收益 = `Σ_{A 选} (a−b) + Σ_{B 选} (b−a)`，只与选点集合有关（可加）。

## 二、一对的结构

把 A、B 各一个配对成"一对"，按左右位置分两种：

| 类型 | 位置关系 | 对中间 `[l, r)` 前缀的影响 | 可行性 |
|---|---|---|---|
| **AB 对** | A 在左 `l`，B 在右 `r` | `+2`（A 抬、B 落，中间净增） | **永远安全** |
| **BA 对** | B 在左 `l`，A 在右 `r` | `−2`（B 落、A 抬，中间净减） | 需中间最小前缀 ≥ 2 |

**贪心**：每次取"收益最大的一对"（AB 对中选 `max(A_l + B_r)`，BA 对中选满足安全条件的 `max(B_l + A_r)`），翻转后更新前缀、把这两个位置从候选删除，再取下一对。

正确性：收益可加、约束只与"B 相对 A 的位置"有关，配对结构使每一步选择互不干扰——最优解可交换为贪心逐对选取且收益不减（本实现以 300 组全枚举暴力对拍实证；这也是"最大收益 + 前缀容量约束"类匹配问题的标准贪心形态）。

## 三、线段树维护什么

每个节点（区间 `[l, r]`）维护：

| 字段 | 含义 |
|---|---|
| `minPref` | 区间最小 `pref / 2`（支持懒标记区间 ±1，即前缀 ±2） |
| `mxA` / `mxB` | 区间内 A 型 / B 型单点最大收益（含位置） |
| `bestA` / `bestB` | 从"区间最小前缀位置"起后缀中最佳 A / B（用于跨区间安全配对） |
| `bestAB` | 区间内最佳 **A 左 B 右** 对（安全，直接可执行） |
| `bestBA_safe` | 区间内最佳 **B 左 A 右** 对且满足"中间前缀 ≥ 2"（直接可执行） |
| `bestBA_any` | 区间内任意 B 左 A 右 对（仅合并中间量） |

合并要点：`bestBA_safe` 的跨左右组合只取"最小前缀位置之后"的 B 与右段 A——因为安全区从全局最小前缀之后开始，保证中间前缀不会跌破 2。

## 四、主流程

1. 读入，算 `pref`、`diffCnt = #(S_i≠T_i)`、初始权重 `wt = weight(S)`；
2. `build` 线段树；`answer[0] = wt`；
3. 循环 `m = diffCnt/2` 次：
   - 取 `d = max(bestAB.v, bestBA_safe.v)`，得一对 `(l, r)`；
   - 若取 AB 对：`[l, r−1]` 区间前缀 +2；否则（BA 对）区间前缀 −2；
   - 删除位置 `l`、`r`（置 `−inf`，不可再翻）；
   - `wt += d`，`answer[2c] = wt`（翻 `c` 对后的最优权重）；
4. **回答每个 k**：恰好选 `k` 个位置 = 翻 `c` 对（占 `2c` 个不同位置）+ 在 `S_i == T_i` 的 `(n − diffCnt)` 个位置中任选 `k − 2c` 个（不改变序列）。故可行 `c` 满足 `2c ≤ k ≤ 2c + (n − diffCnt)`，即
   `answer[k] = max{ answer[2c] : c ≤ k/2 且 2c ≥ k − (n − diffCnt) }`
   用**滑动窗口（单调队列）**对每个 `k` 在线取窗口 `[k − (n−diffCnt), k]` 内 `answer` 的最大值，窗口内 `answer[奇数]` 为 `−inf` 自动被排除。

## 五、复杂度

- 每次翻转对：线段树区间加 + 删点 + 取根 `O(log n)`；
- 共 `m ≤ n/2` 对：`O(n log n)`；
- 回答阶段：单调队列 `O(n)`；
- 总复杂度 `O(n log n)`，`Σn ≤ 5×10⁵`，完全可行（本机 `n = 5×10⁵` 单组约 0.8s）。

## 六、验证

- 5 组官方样例输出逐一比对，全部一致；
- 300 组随机小数据（`n ≤ 10`）与"全子集枚举暴力"三方对拍（暴力 = 参考实现 = 本实现），0 差异；
- 大数据冒烟：`n = 5×10⁵`、`m = 2.5×10⁵` 对，约 0.78s 完成。

## 常见误区

- **以为可以单翻**：翻 `(`→`)` 必须同时翻一个 `)`→`(`，否则括号失衡，序列必然非法；
- **忽略 BA 对的安全约束**：B 在左 A 在右会把中间前缀压低 2，只有中间最小前缀 ≥ 2 才可执行；A 左 B 右则永远安全；
- **忘记相同位置补足 k**：`S_i == T_i` 的位置替换不改变序列，`k` 的奇偶与超出 `2m` 的部分全靠它们凑足——这是输出阶段滑动窗口的由来；
- **无解判定**：本做法里任意 `k` 都可用"c = 0 + 相同位置"兜底（若 `n − diffCnt` 足够）或取可行窗口内 `answer` 最大；只有当窗口内全是 `−inf`（即 `diffCnt = n` 且 `k` 逼着必须翻奇数量位置）时对应 `k` 才输出 `−1`，由 `answer[奇数] = −inf` 自然体现。
