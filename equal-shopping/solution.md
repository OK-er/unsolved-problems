# D - Equal Shopping · 解题思路

## 一句话思路

**三维生成函数 / 背包 DP**。每家店是一个"因子"，金额差（高桥总金额 − 青木总金额）作为背包的"重量"，`P`、`Q` 作为店数维度：

```
dp[t][a][s] = 已处理若干店后，高桥 t 家、青木 a 家、金额差为 s-OFF 的方案数
```

每次修改后对全部 N 家店重跑一遍 DP。关键约束 `N × M ≤ 2000` 保证这样做可行。

## 一、建模

每家店只有三种互斥状态，贡献分别为：

- **无人**：计划数不变（乘以 1）；
- **仅高桥**：在 `[L,R]` 选金额 `w`，高桥店数 `+1`，金额差 `+w`；
- **仅青木**：在 `[L,R]` 选金额 `w`，青木店数 `+1`，金额差 `-w`。

初始化 `dp[0][0][OFF] = 1`（`OFF = 60`，金额差 0 的偏移），逐店转移：

```
无人:  ndp[t][a][s]   += dp[t][a][s]
高桥:  ndp[t+1][a][s+w] += dp[t][a][s]   (w ∈ [L,R], t < P)
青木:  ndp[t][a+1][s-w] += dp[t][a][s]   (w ∈ [L,R], a < Q)
```

答案：`dp[P][Q][OFF] mod 998244353`（高桥恰好 P 家、青木恰好 Q 家、金额差 0）。

**正确性要点**：三种转移都从**旧** `dp` 出发且写入不同目标状态，天然保证"同一家店两人不能同时购物"；金额在 `[L,R]` 内每个整数算一个方案，与题面"不同金额算不同计划"一致。

## 二、状态规模与金额上界

- `P, Q ≤ 3`，每家金额 ≤ 20 → 每人总金额 ≤ `3 × 20 = 60`；
- 金额差 `s ∈ [-60, 60]`，共 `121` 个取值。

## 三、前缀和优化

每个店对每层 `(t, a)`：

- 构造 `dp[t][a]` 的前缀和 `pref`；
- **高桥**：`ndp[t+1][a][s] += Σ_{w∈[L,R]} dp[t][a][s-w]`，即区间 `[s-R, s-L]` 的和 → O(1)；
- **青木**：`ndp[t][a+1][s] += Σ_{w∈[L,R]} dp[t][a][s+w]`，即区间 `[s+L, s+R]` 的和 → O(1)。

每店复杂度 `O((P+1)(Q+1) · 121)`，约 `4×4×121 ≈ 2000` 次。

## 四、复杂度

- 每次修改后全量重算：`O(N · (P+1)(Q+1) · 121)`
- 总复杂度：`O(N·M·(P+1)(Q+1)·121)`，由 `N×M ≤ 2000` 知上界约 `2000 × 4 × 4 × 121 ≈ 3.9×10^6`，远超时限。

空间：`O((P+1)(Q+1)·121)`。

## 五、样例验证

本机编译运行全部 5 组官方样例（含 `40 3 3 50` 的大样例 4，50 行输出），结果与题面完全一致：

| 样例 | N P Q M | 输出首行 | 官方首行 | 全组一致 |
|---|---|---|---|---|
| 1 | 3 1 1 3 | 8 | 8 | ✓ |
| 2 | 4 1 2 4 | 0 | 0 | ✓ |
| 3 | 10 2 2 8 | 58626 | 58626 | ✓ |
| 4 | 40 3 3 50 | 586595877 | 586595877 | ✓（50 行全对） |
| 5 | 2 1 1 1 | 2 | 2 | ✓ |

另用 Python 暴力枚举（状态 × 金额全展开）对拍样例 1/2/3/5，结果一致。

## 常见误区

- 不要把"金额范围"当作单一金额——`[L,R]` 内每个整数都是不同的购物计划；
- 修改是累积的，且每次修改**只影响一家店**，但答案依赖全部店的组合，最稳妥的做法是修改后全量重算（`N×M ≤ 2000` 允许）；
- `P+Q ≤ N` 保证高桥与青木的店数可同时满足；若不加检查，DP 会自动得 0（人数不足时 `dp[P][Q][·]` 恒为 0），无需特判。
