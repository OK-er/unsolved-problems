# E. Prime Destruction · 解题思路

## 一句话思路

**每个数独立拆解**。设 `g(x)` 为把 `x`（连同操作产生的所有后代）全部拆到 `≤ k` 的最少操作次数，则 `f(k) = Σ_{a_i > k} g(a_i)`，且

```
g(x) = 0                                              (x ≤ k)
g(x) = min_{p | x, p 为质数} ( 1 + p · g(x/p) )       (x > k)
```

用最小质因子筛（SPF）预处理质因子，从小到大递推，`O(n log log n)` 每组。

## 一、操作的本质

一次操作：`x → p 个 x/p`（`p` 是 `x` 的质因子）。

- 一个数被拆成 `p` 个**更小**的数（`x/p < x`），所以拆解过程必然终止；
- 各原始元素之间互不影响，总操作次数 = 每个元素的拆解操作次数之和。

因此问题归结为：对单个 `x > k`，求最少操作次数 `g(x)`。

## 二、DP 推导

对 `x > k`，第一次操作必然选择 `x` 的某个质因子 `p`：

- 消耗 1 次操作，得到 `p` 个 `x/p`；
- 之后每个 `x/p` 还需要 `g(x/p)` 次操作（它们彼此独立）。

所以：

```
g(x) = min_{p | x} ( 1 + p · g(x/p) )
```

其中 `p` 遍历 `x` 的所有**不同**质因子即可（同一质因子重复选择不改变结果，取 min 无影响）。

- `x ≤ k` 时已经达标：`g(x) = 0`。
- 递推合法性：`x/p < x`，从小到大计算即可。

### 上界观察

`g(x) ≤ x - 1`（当 `k=1` 时把 `x` 完全拆成 `1` 需要的操作数恰好是 `x - 1`：每操作一次 1 变 `p` 份，最终 `1` 的总个数从 1 到 `x`，操作数 = `x - 1`）。所以中间结果用 `long long` 保险。

## 三、算法步骤

1. 预处理 `1..max(a)` 的最小质因子 `spf`（埃氏/线性筛）。
2. 对每组 `(n, k, a)`：
   - 令 `mx = max(a)`；
   - 从 `x = k+1` 到 `mx` 递推 `g[x]`：枚举 `x` 的不同质因子 `p`（用 `spf` 除尽去重），取 `min(1 + p·g[x/p])`；
   - 答案 `= Σ g[a_i]`（`a_i ≤ k` 时 `g=0` 自然不贡献）。

## 四、预处理（SPF 筛）为什么必不可少

### 这道题里预处理在干什么

`g(x) = min_{p|x}(1 + p·g(x/p))` 要求对**值域内每个数**枚举其全部不同质因子；最终答案又要对数组里每个 `a_i` 复用同一份质因子信息。质因子表是典型的"只由值域决定、与查询内容无关"的数据：

- **不预处理的代价**：对每个 `x` 用试除法找质因子需 `O(√x)`，总代价 `Σ_{x≤N} √x ≈ O(N^1.5)`——`N=2×10⁵` 时约 `9×10⁷` 次运算，且每组测试（`t ≤ 10⁴`）都要重复做；
- **预处理后**：SPF 筛一次 `O(N log log N)`，之后每个数的质因子枚举降到 `O(ω(x))`（不同质因子个数，`≤ log x`），并且**跨所有测试组复用**——昂贵的公共计算被摊销成一次。

没有 SPF，这道题的时间瓶颈会从"每组 `O(mx·ω)`"退化成"每组 `O(mx·√mx)`"，正是预处理把多组数据场景下的总复杂度按住了。

### 识别"可能需要预处理"的题目特征（checklist）

下次拿到题，先对下面几条打勾，**命中 2 条以上就应当考虑预处理**：

1. **值域是已知的、较小的整数范围**（如 `a_i ≤ N`、坐标 `≤ 10⁶`）——能开数组/桶；
2. **同一份信息被大量、反复消费**：DP 每个状态、数组每个元素、每次查询都要用（质因子、约数、阶乘、前缀和……）；
3. **这份信息只由"值域上限"决定，与具体输入内容无关**——可以先算好存表（筛质数、阶乘/逆元、ST 表、调和级数倍数表 `cnt[d]`）；
4. **每个状态的转移需要快速枚举"子结构"**（质因子 / 约数 / 倍数 / 区间），枚举代价是主要开销；
5. **多组测试共享同一套表**，预处理一次、多次摊销。

Prime Destruction 五条全中：值域 `≤ 2×10⁵`（1）、每个 `x` 都要枚举质因子（2）、质因子表只由值域决定（3）、转移即质因子枚举（4）、`t ≤ 10⁴` 组共享（5）——这是它必须预处理、且预处理性价比极高的原因。

### 常见预处理的类型速查

| 类型 | 典型用途 | 预处理代价 |
|---|---|---|
| 最小质因子筛 SPF | 质因数分解、质因子枚举 | O(N log log N) |
| 素数表 | 素数判定、枚举质数 | O(N log log N) |
| 阶乘 / 逆元 | 组合数、多项式 | O(N) / O(N + log MOD) |
| 前缀和 / 差分 | 区间查询 | O(N) |
| ST 表 | RMQ、可重复贡献查询 | O(N log N) |
| 调和级数 `cnt[d]` | "d 的倍数个数"类计数 | O(N log N) |
| 桶计数 | 值域统计、去重 | O(N) |

## 五、复杂度

- SPF 预处理：`O(N log log N)`，`N = 2×10^5`；
- 每组递推：`O(mx · ω)`，其中 `ω` 为不同质因子个数（`≤ log n`）；
- 总复杂度：`O(sum n · log n)`，满足 `sum n ≤ 2×10^5`，`t ≤ 10^4` 可过。

## 常见误区

- 不要直接对 `x` 枚举所有拆分方式（指数爆炸），用 DP 合并；
- `p` 是 `x` 的质因子，不是"≤k 的任意数"；质因子本身 > k 时也要拆（如 `g(质数)=1`，一步拆成 `p` 个 1）；
- 同一质因子多重出现时枚举去重即可，不必按次数分支；
- 答案与中间量用 `long long`（单组答案可达 `n²` 量级）。
