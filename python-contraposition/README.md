# Python 写对拍：能力与技巧总结

> 对拍（Contraposition Check）：随机生成输入 → 同时跑「朴素暴力实现」和「高效实现」→ 逐行比对输出。是算法竞赛中验证代码正确性最高效的手段。

本总结基于 unsolved-problems 仓库实际入库题目的对拍实战（Kaky 撞障碍物、Equal Shopping、Flight Route、Jewel Necklace 等）提炼而成。

## 一、为什么用 Python 写对拍

| 优点 | 说明 |
|---|---|
| 暴力写得快 | `itertools` 直接枚举子集/排列/笛卡尔积，按题意直写不优化 |
| 生成器灵活 | 几行随机代码就能覆盖边界、极端、随机三类数据 |
| 无编译负担 | 改一行重跑即可，C++ 改完要重新编译 |
| 调用 C++ 方便 | `subprocess` 把输入喂给编译好的 `.exe`，拿回输出 |
| 可复现 | 固定随机种子，出错后能 100% 复现同一条输入 |

## 二、对拍基本框架（四件套）

```
数据生成器(gen_case)  → 暴力求解(brute)  →  高效求解(solve_fast)  →  比对器
```

1. **数据生成器**：随机产生**合法**的小规模输入；
2. **暴力求解**：按题意直写，允许指数级复杂度（数据小就扛得住）；
3. **高效求解**：通常是编译好的 C++ 可执行文件（或 Python 高效实现）；
4. **比对器**：两者输出逐行比对，不一致即打印输入 + 双方输出并中止。

完整可复用模板见同目录 `checker_template.py`。

## 三、关键技巧（实战提炼）

### 1. 数据生成器设计

- **参数取小**：`n ≤ 8`、值域 `≤ 12` 之类的规模，暴力枚举才跑得动；对拍目的不是压测性能，而是查正确性。
- **固定种子**：`random.Random(固定整数)`，出 bug 后可复现同一组数据，而不是每次随机。
- **保证输入合法**：比如树要连通（先随机生成一条链再补边）、坐标互不相同、`(0,0)` 不设障碍等——按题面约束逐条满足，否则暴力与高效实现都可能在非法输入上行为不一致。
- **覆盖极端**：最小规模（`n=1`/`k=0`）、最大值边界、全部相同、全部互质、递增序列等，专门为猜想的边界写构造。

### 2. 暴力实现的写法

- 用 `itertools.product(*[...])` 枚举每步/每个位置的选择，`combinations` 枚举子集与组合；
- 直接按题意模拟：状态 × 金额、每步 5 选 1、免费边子集 + 普通 Dijkstra……都是"照抄题意"；
- **暴力也可能错**：先拿官方样例人工核对暴力输出，再开始对拍；
- 暴力的作用不只是"判对错"——**它本身是理解题意的试金石**。Equal Shopping 那次，暴力输出与官方样例 2 不符，逼我重新核对题面，最后发现是我记错了样例输出，模型其实是对的。

### 3. 与 C++ 程序交互

```python
r = subprocess.run(["./main"], input=inp, text=True, capture_output=True)
out = r.stdout
```

- 一次调用喂**一组**输入即可，或把多组打包成一次输入（见模板批量模式）；
- `text=True` 处理文本编码；超时用 `timeout=5` 防止高效实现死循环挂死整个对拍；
- Windows 下可执行文件是 `.exe`，路径含空格要写成列表元素而非整串命令。

### 4. 比对与判错

- 输出先 `.strip().splitlines()`，逐行比对（空白差异不算）；
- 需要取模的题目两边都按同一模数输出，直接比整数行；
- 浮点输出用误差阈值而非 `==`（竞赛题多为整数，一般用不到）；
- **失败即停**：`sys.exit(1)` 并打印输入与双方输出，立刻人工分析。

### 5. 随机化与批量

- 一轮对拍跑 200~1000 组随机数据，一次脚本调用完成，全过才放心；
- 换多个种子多跑几轮，覆盖面更广；
- 针对易错点单独写"定向生成器"：比如所有 N 步、全部免费、`k=0`、`k=m` 等。

### 6. 调试流程（对拍失败后）

1. 用打印的失败输入**单独复现**；
2. **缩小规模**：手动把 n 减到 2~3 找最小反例；
3. 在两份实现里加 print，对比**中间状态**（前缀数组、DP 表、可达集合）定位分歧点；
4. 修复后**重跑全部**用例（不要只跑那一条）。

### 7. 常见坑

| 坑 | 对策 |
|---|---|
| 输入格式不一致（多余空格/空行、多测 T 的结构） | 生成器与两份实现用**同一份文本**，保证格式天然一致 |
| 索引偏移（题面 0-based vs 实现 1-based） | 生成器统一按题面索引输出 |
| 暴力超时 | 缩小参数，或剪枝；对拍只查正确性不查速度 |
| 高效实现卡死 | `subprocess` 加 `timeout` |
| PowerShell 里传参/转义 | 把对拍脚本写成 .py 文件再执行，避免命令行内嵌代码的引号地狱 |
| 生成器本身有 bug | 先打印 1~2 组生成结果人工检查是否合法 |

## 四、实战案例（unsolved-problems 仓库）

### 1. Kaky 撞障碍物（`kaky-obstacles/`）

- 模型：前缀确定位移 + N 步可达集合（曼哈顿 ≤ N 数）
- 对拍：暴力**枚举每个 N 的 5 种选择**（`itertools.product`，`5^n`），对前缀判定法
- 价值：直接验证了「N 步可原地 → 无奇偶约束」这个最易错的直觉；200 组随机全过

### 2. Equal Shopping（`equal-shopping/`）

- 模型：三维背包 DP（店数×店数×金额差）+ 前缀和优化
- 对拍：暴力 `itertools.product` 枚举「状态 × 各店金额」，对 DP
- 价值：**抓出了我对样例 2 的误读**——暴力输出 0,0,0,0 与官方一致，证明模型正确、记忆错误

### 3. Flight Route（`flight-route/`）

- 模型：分层图最短路（`dist[v][used]` 二维 Dijkstra）
- 对拍：暴力**枚举免费边子集**（`itertools.combinations`）+ 普通 Dijkstra，对分层图
- 价值：验证了「免费次数不必用完」「k=0 退化普通最短路」等边界；150 组全过

### 4. Jewel Necklace（曾入库后被删）

- 结论：K 恒为 2、答案恒为 N−2（反直觉的平凡结论）
- 对拍：暴力枚举全部子集求 G、K，与调和级数求 G 对拍
- 价值：**用对拍给一个"可疑的简单结论"背书**——1400+ 组数据无一反例，才敢相信

## 五、何时用对拍

- ✅ 高效实现写完后、提交前（尤其 DP/贪心/构造类，容易想错）
- ✅ 推出反直觉结论时（先对拍背书，再写证明）
- ✅ 卡样例或 TLE 怀疑实现细节时
- ❌ 不需要：纯模拟、按题意直写的题；对拍无法验证性能（那用极限数据压测）

## 六、对拍之外

- **官方样例先行**：任何对拍之前，先把题目给的样例跑一遍；
- **极限压测**：对拍查正确性，性能用最大规模数据单独计时；
- **手造定向用例**：针对每个"常见误区"（见各题 solution.md 的误区小节）写一个用例。
